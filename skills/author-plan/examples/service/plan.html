04Interface and transaction contract

Submit(ctx, authenticatedTenant, key, validatedBody)
  → {status, contentType, responseBody} | validation/conflict/storage error

BEGIN
  INSERT replay slot (tenant, key, body_digest) ON CONFLICT DO NOTHING
  if inserted:
    INSERT job
    UPDATE replay slot with job_id + exact response
  else:
    SELECT committed replay slot in a new READ COMMITTED statement
    compare digest → replay or conflict
COMMIT

The replay slot and job are invisible until commit. A conflicting insert waits for the first transaction to commit or roll back. If it rolls back, the other insert may succeed. Bound waits with the request context and database timeouts.
